# 领域说明

观众研究数据来自问卷、传感器和派生数据集，每项使用应受研究目的、同意范围、保留期限与访问角色约束。撤回同意需要传播到仍可定位的下游记录。

`reference/domain.json` 保存公开的同意状态、数据来源和到期动作枚举。正式业务记录应使用随机参与标识，并保留方案版本和下游使用关系。

## 授权链

```
研究方案(版本化) ── 同意记录(目的×版本×保留期) ── 数据集(来源/到期动作) ── 出库登记(下游去向)
```

- **研究方案** `ResearchProtocol`：按版本注册，声明目的、允许来源、字段策略（目的→允许字段）、可访问角色、披露阈值与保留期限。版本只增不减；升级时重估既有同意覆盖，未覆盖的同意在新版本下自动失效于出库闸门。
- **同意记录** `ConsentRecord`：某随机参与标识对某项目的授权，含目的集合、覆盖的方案版本、保留期限与受限字段白名单（`restricted` 状态）。
- **数据集** `Dataset`：登记来源、上游数据集（派生链）、到期动作（`delete` / `anonymize` / `review_hold`）与保留期限。
- **出库登记** `ExportRecord`：每次出库的消费者、字段、行数与参与者指纹，是撤回/到期时定位下游副本的依据。

## 出库闸门

任何新导出前依次核对：项目方案存在 → 角色被允许 → 目的被登记 → 数据来源被授权 → 保留期限未届满 → 字段最小化（申请 ∩ 策略 − 全局黑名单）→ 逐记录核对随机参与标识、记录保留期与同意覆盖（状态、目的、版本、受限白名单）→ 去重参与者达到披露阈值。任一环节失败即拒绝，并汇总全部原因留痕。

## 撤回与到期

撤回同意或保留期届满时，可定位记录按数据集到期动作处置：物理删除、不可逆匿名化（切断标识链接、移除准标识符、时间泛化到天）或复核隔离。下游使用方收到处置事项，确认完成后出库登记转为已处置。全过程写入 hash 链账本，`proof` 类条目即可对外出示的合规证明——只含 HMAC 指纹与计数，不含个人数据。

已撤回身份进入墓碑集合：此后任何采集/补传（包括离线传感器迟到数据）命中墓碑即丢弃并留审计，身份不可重建；重新参与须生成新的随机参与标识。
